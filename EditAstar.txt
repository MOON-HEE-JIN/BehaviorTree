행동트리 지역 점령 시뮬레이션 — A* 별도 분석
분석 기준: 현재 HEAD 273bc06, 참고 feature/tree_adjust_/edit_codex 96ba862
범위: CAstar.h / CAstar.cpp. 내부 소스, 시그니처, 자료구조는 변경하지 않았다.
아래 정적 분석 항목은 재현 절차 제안이며, 실행 검증 여부를 별도로 표시한다.

[A1] Critical — CAstar::FindPath / JT_CreateStartNode
문제: 최초 확장 후 OpenList.empty() 검사 없이 *OpenList.begin()을 역참조한다.
조건: 시작점이 고립되거나 어떤 방향에서도 점프 노드를 만들지 못하는 지도.
영향: 경로 실패를 false로 반환하는 대신 STL assertion 또는 잘못된 메모리 접근.
수정 방안: 최초 및 매 pop 직전에 empty 검사, 실패 시 출력/탐색 상태 정리.
연관 영향: CBT_FindPath가 반환값을 검사해도 A* 내부 크래시는 방어할 수 없다.
검증: 3x3의 중심만 이동 가능한 지도에서 외부 목표를 요청; 고립되지 않은
연결 불가능 지도도 함께 검사. 이번 작업에서는 크래시 입력을 실행하지 않았다.
호출부에 우회 탐색을 추가하지 않았으므로 미해결 Critical이다.

[A2] High — CAstar::FindPath / CAstarGrid::SetWall
문제: 시작/도착 좌표와 시작/도착 벽 유효성 검사가 충분하지 않다.
FindPath는 m_vecMapStat[startY][startX]를 GetWall 검사 전에 직접 접근한다.
조건: 음수, 지도 밖 시작 좌표, 벽 시작/목표.
영향: 범위 밖 접근 또는 경로 계약 불명확.
수정 방안: 입력 경계와 이동 가능 여부를 입구에서 검증하고 실패 계약 명시.
연관 영향: 현재 CMap의 지역 조회 경계 검사는 이 내부 문제를 해결하지 않는다.
검증: -1, width, height 각 경계 및 벽 입력을 ASan으로 검사. 미실행/정적 분석.

[A3] High — CAstarGrid::GetH / CAstar::JT_FindDirNode / CreateGridNode
문제: 대각 비용 D=1.5, 직교 비용 HV=1인데 Manhattan 휴리스틱을 사용한다.
(0,0)→(1,1)에서 H=2 > 실제 이동 비용 1.5로 허용성/일관성을 보장하지 못한다.
이미 발견한 노드의 더 작은 G를 갱신해도 Open/Closed 멤버십을 별도로 관리하지
않으며 닫힌 노드의 재개방 처리가 명확하지 않다. 최초 OpenList도 정렬 전 pop한다.
영향: 최단 경로 보장 불가. 실제 실패 범위는 기준 탐색과 비교해야 한다.
수정 방안: D=1.5에 맞는 octile 거리, 명시적 open/closed 상태와 재개방 정책,
최초 pop을 포함한 최소 F 선택 규칙을 정립한다. JPS 가지치기 조건과 함께 검증.
연관 영향: 지역 목표 거리 가중치는 실제 경로 비용이 아니므로 별도 취급 필요.
검증: 작은 무작위 지도에서 Dijkstra와 성공 여부/총 비용 대조. 미실행/정적 분석.

[A4] Medium — CAstar::listSort / ClearAstarNode / ListClear
문제: 확장마다 linked list 전체 정렬, 탐색 종료마다 지도 전체 노드 순회 초기화.
최악의 다수 요청에서 정렬 비용과 O(width*height) 초기화가 요청마다 누적된다.
GridNode 최초 방문 시 동적 할당도 발생한다. Open/Close list도 노드 할당을 사용한다.
수정 방안: 정확성 수정 후 heap+탐색 세대 번호/방문 목록을 비교 측정한다.
좌표별 불변 맵 버전을 둔 경로 캐시는 정적 장애물/목표에 한정해 평가한다.
연관 영향: 문은 현재 A*에서 벽이 아니며 실제 개폐는 이동 트리가 처리한다.
동적 문 상태를 캐시에 반영하려면 이동 정책과 맵 버전 계약이 필요하다.
검증: 요청 수/확장 수/할당 수, 평균·p95·p99를 지도 크기별 측정. 미측정.

[A5] High — CAstar::FindPath / ResultPath / isStraight
문제: 시작==목표면 false를 반환하고 출력 벡터를 정리하지 않는다. 일반 실패도
출력 벡터를 보장하지 않는다. isStraight는 도착 검사 후 벽 검사라 도착 벽을
확인하지 않을 수 있다. 대각 이동 시 모서리 통과 허용 여부도 명시되지 않았다.
수정 방안: 성공/실패/이미 도착을 명확히 정의하고 출력 초기화 및 도착 벽 검사.
대각 모서리 통과 정책은 게임 이동과 일치시킨다.
이번 호출부 수정: 요청 전 기존 이동 경로 정리, false이면 목표 예약 해제.
A*의 false 계약 자체는 변경하지 않았으며 도착을 성공으로 위장하지 않는다.
검증: 회귀 테스트에서 실제 시작==목표 false와 호출부 경로/예약 정리를 확인.
도착 벽 및 최단성 비교는 이번에 실행하지 않았다.

[A6] High(향후 병렬화 전) — CMap::m_astar 및 CAstar의 탐색 멤버
문제: OpenList/CloseList, 시작/도착 좌표, 셀별 GridNode를 한 인스턴스가 공유한다.
현재 로직 스레드에서는 직렬 호출하므로 A* 요청 간 데이터 경합은 확인되지 않았다.
조건: 향후 Entity 병렬 Tick에서 같은 CMap에 동시 FindPath 요청.
영향: 탐색 상태 손상, 잘못된 경로, iterator/parent 무효화.
수정 방안: 불변 지도와 요청별 탐색 컨텍스트를 분리하거나 워커별 인스턴스 사용.
검증: 요청별 결과 비교, 동시성 검사 도구, 대량 요청 큐의 지연 분포 측정.
현재 병렬 A*를 도입하지 않았다.

결론: 정상 제공 지도에서의 전체 시뮬레이션 성공은 A1~A3의 안전성/최단성을
보증하지 않는다. A* 내부 개선은 별도 작업에서 Critical부터 처리해야 한다.
